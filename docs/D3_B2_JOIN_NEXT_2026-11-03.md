# D3-B2 — JOIN NEXT (active feature branch; owner phone testing pending)

## Purpose and gameplay contract
Late-arriving LAN guest starts as a **read-only spectator**. Explicit **JOIN NEXT** requests only a future seat, never the current bot actor. The host validates a version-2 packet (active match ID, current lobby revision, one increasing guest request sequence) and acknowledges **QUEUED** or **SPECTATOR** on cancel; stale/malformed packets cannot seize the seat. The host is the only authority on the eventual next-boundary promotion. The new human has the reserved guest faction/color, **fresh personal KOs**, and the prior faction's Best-of-3 series wins, if a playable round remains.

## State transitions and safety
- Request/cancel via live spectator HUD. The status badge and button show real confirmed host state, not optimistic local queue success.
- Original B1 spectator continues watching/receiving live state while queued. All movement/fire/interact remains physically denied; bot seat 1 stays controlled by real host AI. Match clock and score remain unchanged.
- At a completed host fight, the existing **NEXT ROUND / NEW SERIES** control calls `resetAll`; if and only if connected and queued, host switches `lanHostSolo` to false for the newly initialized match and emits a match-bound `join-next-promote` notice **before** new state. No extra actor/swap mid-round, no inherited personal KO or rewarded credit.
- Guest checks previous match, room revision, role and next match ID, then waits for the exact host-authoritative new state to drop read-only spectator mode and regain touch controls. A premature or forged snapshot alone never enables controls.
- Once promoted, old/stale guest input, fire and interact messages require a matching **current matchId** and **room revision**. The host neutralizes stale guest controls before promotion. Disconnect while remote human is active lets real AI take the reserved team seat without changing faction or pausing host.
- Returning to lobby to edit rules clears a pending live queue; the ordinary existing Ready lobby is used for new rules. Native Java packet allowlists explicitly recognize `join-next`, `join-next-status`, and `join-next-promote`.
- B2 still has **one remote guest max**. Native repeated accept/reconnect, network busy/open status, background hosting and two physical phones remain D3-C.

## Reality and release gate

It covers request/cancel, bad revision, wrong match, replay, no mid-fight controls, new series round, personal score reset, faction colors, snapshot authorization and bot fallback. Existing B1/legacy LAN and AI regression suites must stay green. A separate Android build and a **same-developer-test-signer higher-version owner preview** are required before physical-phone review. Do not merge to main or advertise production Wi-Fi until required QA passes.

## Caveat to verify
The queued boundary label says NEXT ROUND when an unfinished best-of-three series has a possible future round; if a round clinches the series, the safe promotion occurs at the next new match instead. Never start a nonexistent round just to satisfy the queue. One-phone owner UX review and full two-phone test remain pending.

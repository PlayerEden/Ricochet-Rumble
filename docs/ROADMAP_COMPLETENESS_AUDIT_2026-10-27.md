## Scope discipline — do not let the wishlist delay a good game

**Recommended minimum launch discussion (decision needed):** Is v1.0 an offline-first game with **three fully working modes** (pilot-only CQC, scored FFA, scored TDM), accessible tutorials, procedural fairness and reliable saving, with optional LAN only if genuinely tested? Or is LAN essential at launch? Do **not** assume the user has chosen a launch-scope policy. The roadmap currently places LAN device QA in release readiness while the owner has deferred it.

**Recommended default** until a decision: target a fun, self-contained offline-first core; hold CTF, Elimination, XL, paid cosmetics, online PvP and leaderboards as post-v1 candidates unless their value/QA evidence clearly justifies launch scope. An *implemented and tested* Pilot Dossier with a small free cosmetic set can be an optional stretch, not a blocker to the combat experience. Do not claim the game can ship without examining Play policies/owner account requirements at submission.

### Decisions still to make — not missing documents

1. **Launch definition:** Must v1.0 contain LAN? Are CQC + scored FFA + TDM all required, or could an earlier public beta ship a smaller polished set? **Owner decision pending; tracked in [#30](https://github.com/PlayerEden/Ricochet-Rumble/issues/30).**
2. **Progression scope:** Small offline Dossier with free cosmetics in v1, or add only after core mode quality? If implemented, choose verified local saves/migrations and prevent duplicate grants.
3. **Monetization:** Prefer no ads/purchases until player experience proves worth it; first paid content, if any, should be gameplay-neutral and properly fulfilled. No consent or transaction implementation exists yet.
4. **Difficulty and retention targets:** Set target session length, bot competence, learning curve, active combat time and whether players choose NEXT MATCH repeatedly, then collect real-device observations to calibrate.
5. **Design document status:** Several Bibles still correctly say *draft/not implemented*, but parts of Quick Play are now implemented **on a draft PR**; don't delete their planned sections or claim everything in a Bible is shipped. Update their implementation status at merge, not before.
6. **Public project licensing/identity:** A public repo without a LICENSE needs an explicit distribution/licensing decision; public access is not automatic permission to reuse third-party assets. Confirm Sector Rebound branding/legal checks before publishing.

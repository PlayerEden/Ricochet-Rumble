# D3 — Persistent LAN rooms, solo-host bot play and drop-in spectators
**Owner-approved direction / implementation not started — 2026-11-02 (Kentucky local).**
**Dependency:** [D2 verified browser/Android work](../LAN_SERIES_D2_2026-11-02.md), signed experimental v0.9.71 source `333fc9d9ffc5f5ff5e136121217240112def531e`, [PR #97](https://github.com/PlayerEden/Ricochet-Rumble/pull/97). The experimental APK is **not** two-phone accepted. Stable `main` remains untouched. Separate plan/implementation branches and owner acceptance gates required.

## Player promise / product contract
A LAN **room** is a persistent foreground-hosted, same-Wi-Fi session. A **match** is one disposable battle running inside that room. The host can create a discoverable room, select rules, immediately play against bots alone, progress through all supported rounds/series, edit rules between matches, and keep the room available without waiting for another phone. A joining player sees an honest room status. If a match is running, they watch immediately, choose **JOIN NEXT ROUND** (where supported) or **JOIN NEXT MATCH**, and enter only at a safe match/round boundary. AI temporarily fills vacant player seats; teams are never reshuffled during combat. Nothing requires internet, a cloud account, room code or a subscription. This is not internet-wide matchmaking.

**Visible states:** `OPEN / IN LOBBY`, `PLAYING / SPECTATE`, `NEXT ROUND RESERVED`, `NEXT MATCH RESERVED`, `ROOM FULL`, `HOST OFFLINE` (last only on connection failure; never imply remotely monitored server). User-facing wording distinguishes 1 human + 3 bots from 2 humans + 2 bots. Lobby rules/AI/factions/KO target/rounds visible before queue; host always owns the authoritative outcome.

**Important limitation:** The room is only live while the Android host is running in the foreground and Wi-Fi networking remains available. Android's current `onStop` closes the network; do not market it as background hosting. One remote device / spectator maximum in D3; multi-spectator server fanout is a separate later scope.

## Current hard constraints, verified from source
- Android `MainActivity.java` currently creates `new ServerSocket(0, 1)`, calls `accept()` **once**, and attaches a single `connection` and `out` writer. On disconnect it notifies JS; it does not return to accepting subsequent clients. NSD advertises a constant name, with no active-round metadata; service discovery only provides name/IP/port.
- In `web/game.js`, `lanCanStart()` requires a connected, Ready guest; `host()` initializes a match with **two human seats**, then waits in lobby. Host snapshots `serializeState()` around 11/s when guest connected; guest sends input around 20/s. `validRemoteSnapshot()` validates the snapshot structure. Android packets are capped at **32,768 characters**.
- D1/D2 scored LAN teams already use real team IDs; 0/2/4 additional bots supports 1v1, 2v2 and 3v3 with two reserved players. D2 best-of-three uses host-authoritative `lanSeries` with no guest scoreboard authority.
- Existing playable Solo mode must **not** be relabeled as a network room. Existing save records, camera, combat, pilot, bot aiming and signer must be protected.

## Scope decisions and reserved-seat model
1. **Permanent room owner:** seat 0 = local human host, always. Seat 1 = *reserved remote seat*; while unoccupied in an active room, a real AI controller drives that actor, not a dummy idle player. On joining, the remote client **first spectates** and has no movement/FIRE/damage authority. The host promotes seat 1 to human only on an eligible round/match boundary, with a deterministic controller swap and fresh spawn. On leave, AI takes over at a safe boundary (or controlled, explicit takeover on mid-match disconnect only after neutralizing inputs and marking the actor AI); never leave ghost FIRE.
2. **Preserve roster/team IDs:** For scored TDM, preserve actor-index and team identity throughout each round. A host-only "2v2" is **host + 1 allied AI versus 2 enemy AI**. When one human joins, that enemy AI seat becomes the guest human, leaving host + ally AI vs guest + ally AI. In a "1v1" room with one device the opponent is a bot, not an empty team. Host faction Cyan/Coral stays real and consistent on both devices. Show roster accurately before and after promotion.
3. **Do not confuse humanCount with active humans.** The engine today uses `humanCount` to separate bot simulation from human seats. Introduce a source-of-control table / role-aware actor interface, distinguishing reserved seat count from live humans. Audit `botBrains`, AI update loops, team/FFA labeling, projectiles, respawn, in-vehicle control, pilot-only, all visibility/privacy filtering, scoreboard, achievements and effects. Do not simply set `humanCount=1` on the host and expect guest slot 1 to remain safe.
4. **TDM series policy:** A spectator can queue for the next round if that series has an unplayed round; new human inherits only the faction/team series score, not prior personal KOs, medals, or rewards. A finished/clenched series queues them for the **next fresh series**. Queue does not modify current score or reset a live fight. For scored FFA, Survival, Co-op and other LAN modes, begin by offering **NEXT MATCH** unless each mode's bot-fill/side semantics have passed targeted tests; do not silently present unsupported next-round entry.
5. **Single guest initially:** one remote TCP connection can occupy spectator/queued/player status. Second remote device receives an explicit BUSY/FULL response when the native listener supports it; it never hijacks the active client or host. Multi-spectator fanout, invites/friends, internet rooms, migration to a dedicated server and reconnect tokens are a later architectural milestone.

## UX / navigation
**Host**: `PLAY TOGETHER → CREATE LAN ROOM → SETTINGS → OPEN ROOM`; header includes room name/host address and `DISCOVERABLE` / `PRIVATE BY IP`, status, current mode/round, player and bot counts. `START VS BOTS` is always enabled for a legal solo-host room. After Action: `NEXT ROUND` (when series ongoing), `NEW MATCH / SERIES`, `CHANGE RULES`, and `CLOSE ROOM`. Going back to lobby never silently tears down the host socket. A visible `HOST ONLY (BOTS)` indicator prevents claiming a second human joined.
**Joiner**: `BROWSE NEARBY → room card (host label, mode, status, bot/human count, current round) → JOIN`. In `OPEN`, enter waiting room and Ready. In `PLAYING`, enter **SPECTATING**, get a current snapshot and truthful scoreboard; `QUEUE FOR NEXT ROUND/MATCH` and `CANCEL QUEUE`. An optional follow-actor camera first; free camera only after touch/layout/privacy/performance validation. NO spectator movement/fire/interact packet accepted. Honor landscape and portrait safe areas and existing thumb controls.
**Privacy**: use short local room labels (validated/escaped), public-to-local-network status only; no profiles/phone identity in network broadcasts. Host can mark private and optionally require approval, but approval comes after basic state-machine and transport correctness. Do not expose any secrets, device IDs or cloud IDs.

## State machine and authoritative protocol (design only)
`ROOM_CREATED → LOBBY_OPEN → MATCH_ACTIVE ↔ ROUND_RESULT → LOBBY_OPEN / CLOSED`. Peer substate independent of match: `NONE → CONNECTING → SPECTATOR → QUEUED → ACTIVE_PLAYER → DISCONNECTED`. Pause keeps room and peer identity but suspends simulation; a match result freezes score before queue promotion.

Transport plan: a deliberately **versioned room protocol** (v2) alongside legacy D2 v1. Negotiated `hello/hello-ack` announces protocol/capabilities; version mismatch fails visibly without simulating game; room `status` metadata describes phase/round/slots; `join-request`, `spectator-joined`, `queue-request`, `queue-ack`, `queue-cancel`, `role-change`, `ready`, `start`, `state`, `heartbeat` and `leave` are allowlisted by actor role and direction at native bridge **and** JS. Use monotonic room revision + match/round ID and bounded packet schema. Guest commands carry seat/match/revision intent and are rejected if stale/duplicate/unauthorized. Only host authors physics, team assignment, KO scoreboard, series ledger, actor-controller transitions and role promotion.

For native Android hosting, replace one-shot accept with an isolated lifecycle-safe accept loop; keep discoverability while a match runs; refresh NSD TXT/status carefully (no rapid unregister/reregister storm), with authoritative status on connection and IP fallback. The native host accepts at most one approved live peer; extra socket attempts return compact FULL/CLOSED status and close. Bound snapshot size/rate, enforce stale-input timeout, close sockets on `onStop` with honest UI, handle rapid leave/rejoin without leaked threads. Before commit, specify how late spectator receives complete **initial scene + scoreboard** and then validated incremental snapshots without temporarily acting as guest seat 1. Reuse current 32KB payload limit unless measured evidence justifies a protocol redesign. A host alone must still have a functioning arena when `connected=false`.

## Mode-by-mode entry / actor budget
- TDM 1v1 (2 actors): host seat 0 human; seat 1 bot until queued guest becomes human. TDM 2v2 (4 actors): host + allied bot vs seat 1 bot + enemy bot until promoted; after promotion host+bot vs guest+bot. TDM 3v3 (6 actors): host+2 bots vs enemy 3 bots until promotion; after host+2 bots vs guest+2 bots. Preserve frozen `teamIds`, vehicle ownership, AI skill and FF. Fixed 2/4/6 total actors; no >6 workaround.
- FFA host-alone: one human, opponents AI and no fake HUMAN label for vacant player. Queue joins next match to avoid changing an FFA result in progress.
- Team Survival and Co-op: keep old win/life semantics; explicit compatibility testing before exposure. Co-op without opposing bots remains invalid. No personal-scored stats for a round watched only as a spectator.
- CQC/pilot-only/custom: reuse game modes only after confirming their original body/control/round semantics and fair bot seat takeover; unsupported modes are disabled with explanation, not silently given wrong rules.
- Host-only kills against bots should not be misreported as a real LAN win against another human. No LAN room automation should grant Solo Dossier/daily rewards unless existing offline policy explicitly covers that specific match type.

## QA: cross-cutting failure matrix and stop rules
1. No guest ever joins; 1v1/2v2/3v3 bot host play, three rounds, manual new match, lobby changes, pause/resume, home-screen exit. No idle ghost player, impossible victory or zero-bot empty target.
2. Join early (lobby) and join late (active); busy room, private-by-IP, stale NSD record, wrong protocol version, same service on multiple rooms, no Wi-Fi, IP fallback.
3. Spectator cannot fire, move, interact, affect scores, set team IDs or claim Dossier rewards. Opponent AI still fires normally while spectated. Backing out has no host simulation change.
4. Queued player enters exactly once at permitted boundary; remains correct Cyan/Coral side; host/guest UI and mirrored team colors agree; round/series KOs carry correctly; new match resets series. Existing FF ON/OFF and bot targeting behave the same.
5. Disconnect as spectator/queued/active; reconnect before/after host rematch; remote input stops within old 0.4-s freshness timeout; no extra death credited by disconnect, frozen results remain immutable; host continues AI-only.
6. Replay stale, missing, malformed, oversize or unauthorized packets; no duplicate promotion, denied second socket, socket closure during Android pause/stop, process restart with no bogus "still online" claim.
7. True mobile geometry, 740×360, 915×412, 1280×720 + portrait; no frame/input stalls vs v0.9.71 baseline; capture real screenshot artifacts, source SHA, APK signer/version, and rollback path.
8. **Critical freeze rule:** if host-only gameplay/legacy LAN, scoring, saves, or update signing regress, stop and return to v0.9.71 checkpoint. Do not integrate D3 into stable `main` or market as fully working LAN until two actual phones verify it.

# Sector Rebound — A2 shared ballistic trajectory core
**Date:** 2026-11-02. **Experimental branch:** `experiment/trajectory-physics-core-a2`, based on the audited pilot-turn parity stage `experiment/combat-parity-trajectory-a1`. **Status:** source implementation, independent ballistic contract and whole-game regression; no owner APK or release approval.

## Implemented
- `projectileOrigin(t,angle,foot)`: one physically validated pilot weapon-hand and tank/mech muzzle placement for live firing and trace. No offset gun through nearby walls.
- `makeProjectile(t,owner,angle)`: common bullet type/speed/lifetime/rapid-fire settings. The same object shape drives live bullets and non-mutating prediction. Ammo caps, shot cooldown, shield cancellation, hit/KO behavior remain owned by `shoot()`.
- `advanceProjectileMicrostep(b,dt,onBounce)`: one x-then-y collision and reflected-velocity microstep, same bumper normal/impulse, small post-bumper immunity and bounce limits. Live projectiles supply an effect callback; predicted traces pass none.
- `traceProjectile(t,angle,options)`: bounded, pure static-world trajectory following the same `STEP` and microstep budget as active bullets. Returns path segments, first reflection, first eligible actor intercept (optional), bounce count and termination reason. It does **not** create bullets, inflict damage, emit FX/SFX, mutate player/bot state or magically account for future target movement. Existing friendly-fire OFF: allied bodies don't absorb friendly bullets. Self-ricochet and shield-on-fire cancellation follow actual bullet rules.
- `previewTrajectory()` is now a thin UI-range policy above the same evaluator: pilot hints ~245 units; tank/mech ~520 units, only first reflection and ~235 after-bounce continuation. This deliberately limits information while making the physics match live shots much better than the old approximate 4-unit/normal-vector preview.
- Actual AI **still uses the old direct-line committed shot policy**. This stage does not grant bots bank shots or alter reaction, target acquisition, damage, HP, turn speeds or ammo. Amber enemy cues unchanged. Upcoming A3 can use limited static trace evaluation.

## Focused verification
- New `tests/ballistic-trace-a2.mjs` is a real-game Node VM fixture (not a mocked pure physics port). It tests pilot/tank/mech muzzle/speed/life parity with actual `shoot()`, fully side-effect-free static enemy hit traces, actor shields, four consecutive live `step(1/60)` positions compared with microstep references, pilot sidearm wall stop, shell wall bounce, short one-bounce UI range, and team-versus-opponent trajectory eligibility.
- Dedicated [fast ballistics workflow](https://github.com/PlayerEden/Ricochet-Rumble/actions?query=workflow%3A%22Sector+Rebound+-+A2+ballistic+contract+%28fast%29%22) validates mirror, game/test JS parse and contract; full [CTF/visual workflow](https://github.com/PlayerEden/Ricochet-Rumble/actions?query=branch%3Aexperiment%2Ftrajectory-physics-core-a2) checks actual input-driven CTF, preexisting pilot/shot/telegraph fairness, 300 Forward Bay seed layouts, saved data, Quick Play, 44 visual snapshots.
- Early CI failures were **test scaffolding**, not automatic proof of gameplay defects: initial string-template escaping and an invalid one-player scored-match fixture. Those were corrected; GitHub CI retains run history for audit. The last gameplay change to verify is trace handling of a shooter's canceled spawn shield; verify whole-game GREEN after it.
